目标：落实用户本轮“三个都要”的开发授权，在现有安卓与 Go 工程中连续交付，不重建项目。
基线：`d5e572a37151ef91201a8fd72dbb2918551ac2ba`；设计沿用布灵，需求见 `docs/product.md`。
执行：原复杂实现者负责后端与共享协议，原 UI 实现者负责原生界面，原验收者独立检查；一个目录只设一个写入者，协议完成后接 UI，不派生子 Agent。

## 统一边界
- 保留现有聊天、任务、个人待办和全部旧资源版本；坏存储失败关闭，不自动覆盖或重置。
- Kotlin Compose + Go 模块化单体；沿用已有依赖和单后端端口。不新建空间、分支、数据库或服务平台。
- 固定安卓设备 `192.168.2.138:5556`，每条设备命令明确 `-s`。保留用户的 8765 预览。
- 不新增外部账号授权、联网工具、任意后端脚本或自动付费重试。开发令牌不进入页面。
- 默认仅阿布已存在；设计稿其他搭子作为可选择的创建预设，创建后才作为真实角色出现，不编造历史、在线状态或消息。
- 本轮开发授权不复用已经完成的上一轮提交口令；不自动提交、推送、发布或归档。

当前进度：A 已独立验收通过；B 正式入口和本地模型桩流程已独立验收通过，真实生成两次尝试失败。用户现已要求提交代码、保留小程序入口，真实生成后续完善；聊天相关功能为当前优先事项。保留常规 WebView 防护和残余联网风险说明，日常小程序 API 查询/读写不调用 AI。

## A：真实多角色与对应界面（先交付）
接口约定：
- `GET /api/bots` 返回 `{bots:[...]}`；`POST /api/bots` 创建；`PUT /api/bots/{id}` 带 revision 更新，冲突不得覆盖。
- Bot 字段：`id,name,instructions,avatar,revision`。默认 id `abu`；头像允许 `abu/leaf/flame/wave/fluff` 五种原创预设；名称 1–40 Unicode 码点，角色说明最多 4000 码点，角色最多 32 个。创建使用客户端稳定 id，重复同内容幂等，异内容冲突。
- 现有聊天和任务 API 增加明确的 botId 归属/筛选；旧客户端不传时兼容阿布。未知 botId 拒绝，不偷偷回退阿布。详情、回复、取消和幂等均核归属。
- 老记录缺 botId 时只归阿布，不丢记录、不破坏旧待办。执行中的任务使用提交时的角色说明快照，编辑角色不能改变已排队任务的职责。
- 角色是配置和隔离上下文，不是模型服务或安全权限；不得因角色说明获得新工具权限。每个角色的模型请求不得混入其他角色历史。

步骤与验证：
- [x] 后端先写角色存储、旧数据兼容、幂等/并发 revision、跨角色读取/回复/取消/上下文隔离的失败测试，再实现。沿用原快照存储方式；有损迁移需另行确认，不在本轮偷偷执行。
- [x] Kotlin shared 添加 Bot 客户端和显式 botId 协议，旧签名默认兼容；MockEngine 核请求字段、错误和取消。后端与共享层交完整可用契约后再接 UI。
- [x] 原生新增创建/编辑角色、实际角色列表/搜索和独立聊天状态；角色切换和令牌换代不能串草稿、pending ID、任务或迟到响应。全局任务页可按角色筛选并显示归属。
- [x] 按原稿调整头像配色/轮廓、列表密度与对齐、详情和创建表单；保留单行输入、双主题和可见前台动效。明确只有已创建的角色为真实功能。
- [x] Go test/race/vet/build、shared/app 测试与 APK 构建；独立用两个真实角色验证职责上下文、历史/草稿隔离、任务归属、重启保持和原数据回归；138 实机深浅/IME/字号验收。

## B：AI 创建和持续修改小程序（A 闭合后继续，不算范围外）
- 从选定角色聊天或小程序中心提出需求，复用持久后台任务生成 HTML/CSS/JavaScript 草稿，不限制成固定组件模板。
- 生命周期：需求→草稿→资源/协议校验→隔离预览→原生可信确认发布→固定入口；修改生成新版本，用户确认后激活，可回退资源，不能悄悄回退数据。
- AI 输出与生成页面均按不可信处理。校验只是格式门禁，不宣称静态扫描能证明安全；必须补齐当前仅支持固定可信待办的动态注册、逐应用来源、资源完整性与受限数据桥隔离。
- 草稿预览不持有生产数据写权限；页面无模型/开发/OAuth令牌、通用原生桥或任意后端执行；限制常规外网加载但不保证所有浏览器通道彻底断网。权限由原生与后端强制，不由模型自报。
- 小程序和聊天操作同一份按应用隔离的数据；模型提出的数据变更必须经原生确认、版本/修订校验和幂等提交，禁止静默覆盖及自动重放。
- 旧 personal-todo v1/v2/v3 保留原始字节、缓存和入口；新应用版本失败不影响旧应用。离线默认只读，不新增离线编辑队列。
- [ ] A 完成后主控据实际角色契约确定生成/发布和数据动作的具体接口及安全边界，再由原复杂实现者连续实现后端/运行时，原 UI 接入对应页面。不能拿硬编码演示页冒充 AI 生成。
- [ ] 本地模型桩测试无效输出、取消/重启、超额资源、恶意路径/网络/跨应用消息、身份切换、预览越权、发布冲突和回滚不丢数据；实际生成与设备验收必须区分桩与真实模型。
- [ ] 最终验收从自然语言生成一个非既有固定模板的应用，预览确认发布、使用、继续修改、回滚，证明聊天与页面数据一致且跨应用不可读写。
