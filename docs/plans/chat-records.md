# 聊天记录闭环

范围：单个主机器人会话的文本发送、持久化历史、重复提交防护；不接模型、不执行任务。
用户已批准继续实现。此切片不等于阶段 1 全部完成。

工程决策：
- 开发环境使用 Go 标准库的本地原子 JSON 快照，最多 200 条、每条 4000 字符；后续生产迁移 PostgreSQL。不新增数据库服务或依赖。
- 仅本机监听；业务 API 必须使用 ABU_DEV_TOKEN（至少 32 字节）认证。未配置时业务 API 不开放。
- 安卓 Debug 设置内输入开发令牌，仅驻留内存，不落盘；重开应用需重新输入。生产配对和密钥存储不在此轮冒充实现。
- GET /api/chat/messages 返回 messages 与 modelConfigured=false；POST 同路径接受 id/content，返回保存结果。相同 id/content 重试不重复写；相同 id 不同内容冲突。
- 开发记录保存在 ABU_DATA_DIR（默认 backend 工作目录下 data），不记录令牌和消息日志。
- 返回后再确认已保存；断网输入保留、可重试。无自动机器人回复。

步骤：
1. Go 测试先覆盖认证、校验、幂等与重启读取，再实现存储/API。
2. 共享 Ktor 客户端测试成功与错误协议。
3. 安卓会话 UI 与 Debug 令牌配置，历史加载、发送、错误提示。
4. Go race/vet/build、Android tests/build/lint，自有模拟器验证；独立验收缺口如实保留。

结果：代码与自动化测试已落盘，真实 Go HTTP 重启持久化通过；安卓 10 项测试、构建及 Lint 命令通过。
