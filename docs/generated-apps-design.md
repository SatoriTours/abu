# AI 小程序生成：实施边界与交付合同

来源：用户已授权三个方向全部继续；本合同细化 `next-iteration-plan.md` 的 B，不改变现有多角色与布灵设计。

当前交付范围：保留小程序入口和现有底座；本地模型桩流程已验，真实生成两次尝试均失败。用户要求先提交代码并优先完善聊天，以下完整真实生成目标暂缓，不作为当前已完成能力。

## 用户已确定的安装方式
- 只安装一个 Abu APK，不引入需要另装的渲染配套应用。继续使用 WebView + HTML/CSS/JavaScript 版本化资源包，不改为自研声明式框架或 WASM 界面。
- 用户在知悉 WebView 无法保证彻底禁止恶意脚本出站后，接受单 APK 常规 WebView 方案。采用多层防护而非 OS 级无网络沙箱，不声称 CSP、拦截或 API 缺失能覆盖所有出站路径。取消“必须先取得 OS 级隔离才能挂载”的产品门槛；资源完整性、来源/会话校验、令牌保护和受控原生确认仍是必要条件。
- 主要用途是生成后长期重复使用：打开、刷新、查询和保存直接走受控 Go API，模型调用只发生在用户明确生成/修改/提出 AI 数据建议时。AI 不是每次操作的代理，也不自动执行生成的 Go/SQL 或另起后端服务。

## 用户流程
从选定角色聊天的明确“创建小程序”动作，或小程序中心的新建入口输入自然语言需求。沿用同一生成任务和草稿，不额外部署服务。普通模型回复里的代码或动作文本不会自动执行。
生成 → 校验 → 原生标识的草稿预览 → 用户确认发布 → 应用中心固定入口；后续自然语言修改生成新草稿，确认后激活新版，可选择旧资源版本。页面回退不回退数据。
聊天内还可针对选定应用提出数据变更，由模型生成操作建议，经原生确认后写入；页面和聊天共用相同修订数据。当前阶段仅用户显式进入的应用动作，不做关键词误触发或自主执行链。

## 范围与约束
- 页面为模型真正生成的 HTML/CSS/JavaScript，不是固定组件模板；首版自包含三文件 `index.html`、`app.css`、`app.js`，单文件不超过 64 KiB，总计不超过 192 KiB。可内嵌 SVG，不拉取外部库或资源。
- 最多 15 个生成应用，保留内置 personal-todo；每应用最多 16 个版本，不自动删除历史。发布上限须明确报错。名称 1–80 码点，需求 1–4000 码点。
- 应用持久数据为 JSON 对象，UTF-8 不超过 64 KiB、嵌套最多 8 层；拒绝重复键、非法 Unicode、非有限数和超出互通范围的数值。修订上限沿用 JavaScript 安全整数。首版不支持自定义服务端代码、SQL 或破坏性 schema 迁移。
- 身份仍是当前个人开发令牌；botId 是作者/上下文，不授予额外权限。应用数据按应用隔离，而不是随当前角色切换所有权。
- 使用已有模型适配器和后台任务队列的单 worker，生成和文本任务都必须有界、可取消、可恢复状态。崩溃重启不得自动重发模型请求。普通聊天/文本任务的原限制不放宽。
- 现有模型输入单消息上限 4000 码点，文本任务输出会截断：生成不能误复用这条截断路径。给模型的代码上下文以有序、明确标记的不可信分片提供，整体有界；模型输出必须完整、严格 JSON，超限/截断拒绝，不截掉代码后冒充成功。
- 不新增依赖、数据库或常驻平台。原 personal-todo v1/v2/v3 资源字节、缓存格式、能力与入口保留，不自动迁移或污染原数据。

## 服务接口方向（具体结构由底座实现者统一落入 docs/generated-apps.md）
- `/api/app-drafts`：创建/列出本人生成草稿，绑定稳定请求 id、botId、需求和可选应用/基版本；修改草稿的目标版本在请求时冻结。
- 草稿详情提供 queued/running/ready/failed/cancelled/interrupted、校验错误和仅已验证的资源清单；可取消、显式新请求重做。预览资源只通过开发令牌由原生下载，不向页面提供凭据。
- `/api/generated-apps`：已发布目录；按应用获取版本清单/资源、读取数据、提交确认的数据修改。
- 发布必须带草稿内容指纹与预期当前版本；重复相同请求幂等，旧版本竞争返回冲突；下载和校验完成前不能替换设备已可用资源。
- 数据使用 `{revision,document}`，原生提交 `{mutationId,baseRevision,document}`；请求完全相同才幂等，冲突保留旧数据与建议，禁止自动覆盖。
- 数据建议由独立的模型工作种类产生，携带应用 id、当前数据修订与用户意图；生成建议不等于确认写入。提交前仍校验修订。
- 不向原 `/api/apps` 旧严格协议直接塞未知能力；独立生成应用端点和协议，由应用中心组合显示，避免破坏旧待办严格解析器。

## 原生容器安全边界
- 每个发布应用/草稿使用独立且可验证的虚拟 HTTPS 来源、版本化白名单资源与哈希校验。源、应用、页面会话代次由原生确定，不信页面自报 appId/botId。
- 强制 CSP、资源请求拦截并限制常见网络通道（不承诺彻底断网）；阻止跳转/弹窗/文件/content URI/iframe/Worker/下载/设备权限；停用 cookie 与 DOM 持久化；不开放通用 JS interface，不把用户令牌或模型密钥嵌入 HTML。
- 仅受控消息端口提供当前应用读取与变更提议，消息有大小、格式、频率和待确认数量上限；无路径、网络、文件、任意方法或其他应用选择能力。
- 已发布页面的数据写入均需要原生可信确认，展示应用与变更内容；页面不得伪造确认事件。取消/切页/换身份使旧确认失效；网络未确认提交持久保留原 id、修订与正文，只有用户明确重试。
- 草稿预览只使用临时示例数据，不连接生产数据写权限；预览退出可丢弃示例变更。离线已发布应用只读已确认快照，不排队编辑。
- renderer 异常、页面卡死或桥泛洪应能退出回原生页面、释放端口，不拖垮应用或循环重开。校验不宣称证明生成脚本安全；WebView 防护与权限边界仍须恶意样本实测。
