# 产品与架构基线

状态：用户已确认方向并授权项目初始化。以下需求来源于本次讨论；技术细节仍需按阶段验证。

## 已确认的主要特性
1. 个人使用，无多人注册、公开发布市场或公开网页入口。
2. 安卓优先；Go 编写后端。
3. 多机器人：一个默认主机器人，可创建多个职责不同的专用机器人，各自执行任务。
4. 日常自然语言对话、记录、笔记及可管理的长期记忆。
5. 布置任务，后台持续执行并返回进度、结果、错误与待确认操作。
6. 用户授权后连接 Gmail 等个人账号，读取获准内容。
7. 机器人能够创建持久可用的小程序，并可持续修改；固定入口位于 APP 内。
8. 小程序支持网页级自由布局与交互，HTML/CSS/JavaScript，不限制为固定组件模板。
9. 所有小程序复用现有 Go 后端及端口，不另部署服务器、不为每个小程序启动服务。
10. 默认采用 PWA 风格工程能力：资源缓存、离线打开、本地数据及受控同步；不提供浏览器安装和外部分发入口。

## 推荐架构
安卓按用户后续要求沿用 Daily：Kotlin Multiplatform + Compose Multiplatform，android/app 为界面层，android/shared 为共享逻辑，版本目录统一依赖；WebView 承载小程序。只沿用框架结构，不复制 Daily 业务、账号或密钥。
Go 采用模块化单体，划分认证、机器人、聊天、记忆、任务、连接器、小程序模块。
机器人是角色、权限、记忆范围和任务的配置实体，不各自部署服务。
PostgreSQL 为规划中的持久存储；初期小程序数据可采用按应用隔离的 JSONB 记录。
静态资源初期使用持久化目录，后续可替换对象存储。初始化阶段不引入数据库依赖。
模型接入统一适配层，不固定供应商。任务在后端持久化执行，不依赖 WebView 存活。
Go 单端口提供聊天、任务、小程序资源、数据及受控动作 API。
未来业务路径建议 /api/chat、/api/tasks、/api/apps；尚未形成正式接口契约。

## 小程序生命周期
自然语言需求 → 生成草稿 → 自动校验 → APP 内预览 → 用户确认发布 → 固定入口。
保存应用清单、资源包、数据定义、权限需求、动作定义及版本。
修改生成新版本，完整校验后切换；保留旧版。页面回退不等于数据库回退。
破坏性数据迁移需独立确认和备份。
前端可自由生成，第一阶段不执行任意生成的 Go、SQL 或服务器脚本。
页面通过受控 SDK 调用数据和动作，服务端始终校验身份、应用权限、输入与额度。

## PWA 与安卓容器
PWA 是性能与离线策略，不是必须向浏览器开放的网站。
版本化静态资源缓存优先；普通数据可显示标记时间的本地快照并联网更新。
敏感授权响应不进入通用缓存。离线写入仅对显式支持的动作开放，需要幂等与冲突处理。
邮件发送、远端删除等敏感动作默认在线确认，不盲目自动重放。
原生容器与 Service Worker 的缓存职责须明确，避免重复更新机制。
本地安全来源、Service Worker 支持、逐应用来源/存储隔离，必须先在 Android WebView 实测。
不得假定 file:// 支持 Service Worker；同域不同路径不是安全隔离。
不依赖 PWA 后台同步维持任务：Go 执行任务，安卓负责生命周期、恢复和通知接入。

## 安全与隐私
个人使用仍需设备认证/配对；不是多人注册系统。
无公开入口不等于接口无法被外部调用；后端每次请求必须鉴权。
不能承诺用户在其控制的设备上绝对无法提取页面资源。
生成代码、邮件及外部内容均不可信，不能扩大权限或改变系统指令。
页面不得获得 OAuth 令牌、模型密钥、数据库凭据或任意原生桥能力。
默认限制外部导航、弹窗、设备文件和外部资源；依赖随资源包交付。
应用分别授权与隔离，委派不提升权限；敏感确认使用原生可信界面。
记忆可查看、修改、删除，不把所有对话自动转为永久记忆。
账号撤销、退出后的缓存清理、数据导出删除、密钥加密和备份恢复须纳入实现。

## 非目标
第一版不做多人 SaaS、公开网站/PWA 安装、应用市场、任意后台代码执行、每机器人容器或微服务平台。
没有批准模型供应商、付费服务、公开部署、自动发送邮件或不可逆操作。
